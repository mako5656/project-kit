# ADR：設計判断の記録

ADR（Architecture Decision Record）は、その時点の前提・課題と、「なぜその仕様・構成を選んだか」を残す文書です。インフラだけでなく、業務仕様・認証・料金・データ構造など、後から理由を知りたくなる判断を記録します。

現在の仕様は`仕様/`を参照してください。ADRは決定時点の記録であり、最新の実装を保証しません。

## 書き方

1. [テンプレート](テンプレート.md)をコピーし、`0001-判断の要約.md`のように連番を付けます。
2. 判断日と記録日を分け、当時分かっていた前提・課題・選択肢・採用理由・不利益を記載します。後から判明したことを当時の判断理由として書き足しません。
3. 状態は「提案」「採用」「却下」「廃止」「後続ADRに置換」を使用し、実装済みかどうかは別に明示します（例：「採用（未実装）」「一部を後続ADRに置換（0012）」）。
4. 採用後に判断を変える場合は、新しいADRを作ります。以前のADRは残し、状態と後続ADRへのリンクを更新します。誤字・リンク切れの修正は可能です。
5. この一覧と関連する仕様・設計資料・Issueからリンクします。運用手順や変わりやすい設定値は対応する資料で管理します。
