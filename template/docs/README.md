# ドキュメント

資料を目的ごとに分類し、設計判断の経緯はADRに残しています。

| 分類 | 内容 | 入口 |
| --- | --- | --- |
| 仕様 | 利用者から見た機能・業務ルール・未実装の範囲 | [サービス仕様](仕様/README.md) |
| ADR | 判断時点の前提・採用理由・選択肢・トレードオフ | [設計判断の記録](ADR/README.md) |
| 開発ルール | コミットメッセージ・ブランチ名の種類（プレフィックス） | [コミットメッセージ・ブランチ名の書き方](開発ルール/コミットメッセージの書き方.md) |

## 資料の置き方

- 業務仕様は`仕様/`、判断の背景と採用理由は`ADR/`へ置きます。
- 必要になったら分類を追加し、この表に追記します（例：実装構造は`設計/`、環境構築・検証の手順は`開発/`、本番の手順は`運用/`、外部の資料は`参考/`）。
- 各分類のREADMEは索引にし、詳しい説明は目的別の文書へ分けます。
- 仕様・参考資料は整理のために削除しません。移動時はリンクと索引も更新します。
